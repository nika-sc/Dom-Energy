# Архитектура

> **Актуально на 4.14 (21.11.2026).** Проверено на живой плате:
> прошивка 4.14, сборка `6fe4b87d3a861ba37f1f`, образ 1 630 192 Б
> (82,9 % слота 1 966 080 Б), страница `/` ~86,3 КБ (86 331 Б отдаётся) Б, `/app.css` 27 437 Б,
> `/app.js` 56 770 Б, `/history.js` 63 122 Б, `/control.js` 5 868 Б,
> `PAGE_CAP` 96 000, HTTP-эндпоинтов 53, скинов 6.
> Экранов **десять определены, девять доступны**: главный, напряжение,
> темп реле, мощность, итоги, погода, климат, настройки, **состояние**;
> «сторож» в коде есть, но отключён (`WD_UI 0`). Калибровки тача в
> настройках нет — она только по serial.
> Новое в 4.14: `/measure`, `/climatehist`, `/storage`, `/stage`, `/weather`,
> `/forecast`, `/shot` (отладочно), `/repair`; экран «СОСТОЯНИЕ»;
> `X-Dom-Key` для изменяющих маршрутов; вынесенные ресурсы страницы.
>
> Основной поток: локальный зашифрованный Tuya query + command 18/DP6 →
> измерения с отдельной свежестью → защита/экран/SD; облако служит резервом.
> `/history`, `/days` и `/range` готовят фиксированные снимки SD небольшими
> порциями в `loop()`, до завершения возвращают 202/pending; живые строки
> продолжают добавляться. За `/range` отвечает `range_reader.h`, ротацию
> сохраняемых месячных файлов — `archive_transaction.h`, HTTP-дедлайны и
> ключ — `bounded_web_server.h`, источник/возраст показателей —
> `meas_sources.h`. Windows и веб ждут полный ответ и восстанавливают чтение
> после временных сетевых ошибок. Новые данные не заменяются старым кэшем
> без отметки об ошибке обновления.
>
> `GET /storage` показывает ёмкость, свободное место, состояние записи и
> ротации. Месячные CSV и ревизии не удаляются по возрасту. Windows-задача
> `DomEnergy-DailyArchive` хранит независимые SHA-256/gzip-снимки SD,
> проверяет объекты и восстанавливает только в отдельную локальную папку.
> Изменяющие HTTP-маршруты требуют `X-Dom-Key`; ключи находятся только в
> установленной конфигурации. Сборка/прошивка — через штатное
> Windows-приложение, версия остаётся 4.14.
>
> Если ниже в тексте встретится «экрана настроек нет», «6 экранов»,
> `PAGE_CAP 32 000», «аутентификации нет», `setInsecure()` или версия 4.4 —
> это устаревшая часть, верьте этой шапке.

> Как устроена прошивка и почему она сделана именно так.

## 1. Что делает устройство

Одна плата ESP32-2432S028 (CYD) раз в ~15 секунд читает реле Tuya по
локальной сети, раз в 30 секунд пишет строку истории на microSD, показывает
данные на экране 240×320 и отдаёт веб-страницу в локальной сети.

```
┌──────────────┐    Wi-Fi 2,4 ГГц     ┌─────────────────────────────┐
│ Реле Tuya    │◀────────────────────▶│ ESP32-2432S028 (CYD)        │
│ 220 В        │  TCP 6668, Tuya 3.5  │                             │
│ DP 1/6/16/101│                      │  экран ILI9341 240×320      │
└──────────────┘                      │  тач XPT2046                │
                                      │  microSD /energy.csv        │
┌──────────────┐    HTTPS (интернет)  │  WebServer :80              │
│ Tuya Cloud   │◀────────────────────▶│                             │
└──────────────┘                      └──────────┬──────────────────┘
                                                 │ Wi-Fi LAN
┌──────────────┐    HTTP (интернет)              ▼
│ OpenWeatherMap      │◀────────────────────  ┌─────────────────────┐
└──────────────┘                       │ Браузер телефона/ПК │
                                       └─────────────────────┘
┌──────────────┐    HTTP (LAN, опция)
│ PC API :8090 │◀──────────────────────  плата (температура,
└──────────────┘                          энергия, сверка)
```

Ключевой принцип: **локальные данные (реле, карта, экран) работают без
интернета**. Интернет нужен только для облака Tuya (мощность/история),
погоды и, опционально, PC API.

## 4. Запуск

```
setup()
  ├─ Serial 115200
  ├─ подсветка (GPIO 21), RGB LED
  ├─ тач: tpInit(), loadCal() из NVS
  ├─ Wi-Fi: loadWifi() из NVS, иначе secrets.h
  ├─ TFT: tft.init(), rotation 0, заставка
  ├─ connectWifi(25 с)
  ├─ configTime(UTC+3), ждём NTP до 20 с
  │    └─ нет NTP → restoreClock() из NVS
  ├─ SD: initSD(), initHistoryMonth()
  ├─ loadToday(), loadPeriods(), loadHistDay()
  ├─ seedStatsFromSd() — мин/макс за сегодня
  ├─ initSD(): при отсутствии /energy.csv — откат из /energy.bak
  ├─ drawScreen()
  └─ webSetup()

С 4.14 первый опрос реле/облака/погоды **не блокирует** старт: сеть
поднимается, веб-сервер отвечает сразу, а данные приходят ближайшими шагами
`loop()`. Если Wi-Fi нет, плата всё равно запускается: экран, карта и serial
работают, но новые данные с реле не приходят. На экране — «НЕТ ДАННЫХ» или
последнее значение.

## 5. Главный цикл

`loop()` — кооперативный, без RTOS-задач. Тяжёлые операции разбиты на шаги,
чтобы тач не «умирал».

```
loop()
  ├─ handleTouch()                  всегда первым
  ├─ histTick()                     дозаполнение истории (шаг за проход)
  ├─ writeSd()                      не чаще 30 с, с проверкой записи
  ├─ netOnline()                    проверка интернета раз в 30 с
  ├─ updateToday()                  раз в 5 с
  ├─ updatePeriods()                раз в 60 с
  ├─ seedStatsFromSd()              пока не получится
  ├─ netStep 1..4                   одна сетевая операция за проход:
  │    1) tuyaQuery()               локальное реле (DP6/DP101)
  │    2) cloudStatus()             облако — резерв, раз в 10 мин максимум
  │    3) fetchFromApi()            PC API, опция
  │    4) pushHistory(), sendJsonData()
  ├─ weather/forecast               по расписанию, не сразу после веб-запроса
  ├─ redraw                         по сигнатуре, не чаще 2 мин
  └─ serial-команды
```

Почему так: HTTP/облако/TLS могут занимать секунды. Если делать их подряд,
тач и перерисовка стоят. Между шагами вызывается `handleTouch()` и
обрабатываются веб-клиенты.

**Честное ограничение 4.14.** TLS облака, погоды и прогноза по-прежнему
живёт в `loop()`: в замерах `loopMaxAll` доходит до 1,8–2,9 с при
`blk=pwrfill/gapfill/облако`. Таймауты TLS снижены, тяжёлая погода не
начинается сразу после обслуживания веб-клиента, перед TLS при нехватке
памяти освобождается кэш суток — но перенос TLS в отдельную задачу **не
сделан** (нужен стенд, риск для рабочей платы).
На каждом шаге в `RTC_NOINIT_ATTR` хранится код этапа: после паники он
пишется в `/boots.log` полем `st=` и виден в `/stage`.

## 7. Tuya local: протокол 3.5

Реле слушает TCP **6668**. Кадр:

```
0x6699 | 0x0000 | seq(4) | cmd(4) | len(4) | IV(12) + AES-GCM + tag(16) | 0x00009966
```

- ключ шифрования — `LOCAL_KEY` из `secrets.h` (16 байт);
- согласование: cmd 3 → 4 → 5, session key = AES-GCM(local_key, ...);
- запрос данных: cmd 16, ответ — `retcode(4) + JSON{"dps":...}`;
- первые 4 байта ответа — **retcode**, а не JSON.

Разбор DP:

```
DP 1   = 1904        → 19.04 кВт·ч
DP 6   = base64(8)   → word0/10 = В, word3 = Вт, байты 2..4 = мА
DP 16  = true/false  → реле
DP 101 = 221         → 22.1 °C
```

## 8. Tuya cloud: HTTPS и подпись

```
stringToSign = method \n sha256(body) \n \n path
sign         = HMAC-SHA256(secret, clientId + token + t + nonce + stringToSign)
```

- host `openapi.tuyaeu.com`, HTTPS 443, проверка сертификата по доверенным
  корням из `trusted_roots.h` (`setInsecure()` не используется);
- токен живёт ~15 минут, кэшируется в RAM;
- статус запрашивается, только если локальные данные устарели; при свежем
  локальном напряжении облако не вызывается, но раз в 10 минут проверяется
  и раз в 2 минуты пробуется, если токена нет (`cHold`, `tok` в `/data`);
- облако даёт `phase_a` — резерв мощности/напряжения/тока;
- история за пропущенные часы — по 100 записей, шагами, без блокировки тача;
- при ошибке TLS суточный кэш отчётов освобождается после сохранения на SD:
  mbedTLS нужен непрерывный блок памяти ~35–45 КБ.

## 9. Расчёты

### «Сегодня»

`myTodayKwh` = прирост счётчика от `dayStartKwh` (или сумма интервалов из
CSV, если карта доступна). Стоимость — по тарифу часа:

```
06:00–23:00 → TARIFF_DAY   (8.39 ₽/кВт·ч в примере)
23:00–06:00 → TARIFF_NIGHT (4.49 ₽/кВт·ч в примере)
```

Тарифы — константы в начале `.ino`; при публикации это **пример**, а не
«правильные» цены.

### «Вчера» и «месяц»

- вчера: `scanSdRange()` по CSV; если пусто — облако (`cloudDayStart`);
- месяц: база на первое число из облака/карты, дальше прирост счётчика;
- стоимость месяца — по `periodTariff()` (90 % день / 10 % ночь), потому
  что суточный профиль 7/24 ночи не отражает реальное потребление.

### Прогноз

`projKwh = myTodayKwh * 24 / elapsed_hours` (не меньше уже съеденного).
`projCost = projKwh * средний_факт_тариф`.

### Мощность

Мгновенная — из `phase_a`; средняя — по часовым средним, текущий неполный
час не учитывается; пик — максимум часовых пиков (или живой максимум).

**Пики по часам.** Для каждого часа с данными `/history` отдаёт:

- `pmax` — максимальная мощность в часе (из записей каждые 30 с);
- `pmaxT` — время этой записи, `ЧЧ:ММ` (у старых часов без минуты — `null`);
- `pmaxDur` — сколько **секунд** час был не ниже 80 % от `pmax`.

Длительность считается по гистограмме мощности часа (`gPkHist`): секунды
раскладываются по корзинам (100 Вт до 2 кВт, дальше 500 Вт / 1 кВт / 10 кВт+),
затем складываются все корзины от порога 80 % пика и выше (`pkDurSec`).
Строка CSV даёт 30 секунд, поэтому разрешение длительности — 30 с. На экране
и странице секунды показываются минутами (`pmaxDur / 60`, минимум 1 мин).

## 10. SD: формат и жизненный цикл

```
/energy.csv                 текущий месяц
/energy-YYYY-MM.csv         архивы прошлых месяцев
/climate.csv                климат: дата, час, t, h, p (раз в час)
/weather.csv                погода по дням
/voltage.log                провалы и всплески напряжения
/boots.log                  журнал загрузок, в т. ч. st=<этап> и rr=OTA
/rangecache.bin             кэш суток для /range
/energy.bak, /energy.tmp    точка откатa и незавершённая запись
```

Строка `/energy.csv`:

```csv
2026-10-30 14:33:07,236,152.0,19.04,1,10.39,22.1
```

Правила:

- не чаще 30 с;
- только при `voltage ≥ 50`, `energy > 0`, валидном времени;
- `cost` — накопленная стоимость с начала месяца;
- `temp` может быть пустым, если датчик ещё не ответил;
- при смене месяца файл переименовывается, новый начинается с заголовка;
- **месячные файлы и ревизии не удаляются по возрасту** (с 4.14 ротация
  только сохраняет историю, `archive_transaction.h`);
- **каждая запись проверяется**: `writeSd()` пишет строку в буфер, сверяет
  возврат записи и причину; счётчики `writeOk/writeFail/writeFailRun/
  lastWriteAgeSec/lastFailAgeSec/lastWriteErr/lastWriteMsg/freeBytes/
  archiveError` — в `/storage`. `-1` в `lastFailAgeSec` = ошибок не было;
- **после обрыва питания** `initSD()` при отсутствии `/energy.csv` возвращает
  `/energy.bak` через `rename`, иначе пробует `/energy.tmp`; пустой файл не
  создаётся;
- **починка дублей** — `GET /repair?dedupe=1` (нужен `X-Dom-Key`): оставляет
  первую строку на каждую секунду, исходник — в `/energy.bak`;
- чтение — блоками 512 байт, с `esp_task_wdt_reset()`;
- `/full` умеет отдавать диапазон `from`/`len`, чтобы не тянуть мегабайты.

Ёмкость: ~2880 строк/сутки × ~55 байт ≈ 160 КБ/сутки, ~5 МБ/месяц.
Карта 8–32 ГБ подходит с запасом.

| Что | Пины | Хранение | Логика |
|---|---|---|---|
| Подсветка | GPIO 21, ШИМ 5 кГц / 8 бит | NVS `disp`: `bright`, `touch` | `0` — погашена; касание при погашенном экране поднимает яркость на 20 с |
| Светодиод | 4 (R), 16 (G), 17 (B), активный низкий, ШИМ | — | приоритет: красный > оранжевый > жёлтый > зелёный; тусклый зелёный = экран погашен |
| Динамик | GPIO 26, ШИМ-тон (канал 1) | NVS `beep`: `on`, `vol`, `touch`, `hour` | по умолчанию выключен; тревоги по напряжению (207–253 В, 10 с) и температуре (> 55 °C) |

Приоритет светодиода считается в `ledWant()` раз в цикл: нет Wi-Fi или две
неудачи реле подряд — красный; нет карты или две ошибки записи — оранжевый
(мигает 1 Гц); нет интернета или три отказа облака — жёлтый; иначе зелёный,
а при погашенной подсветке — тусклый зелёный (20 %).

## 12. Веб-страница

`BoundedWebServer` на порту 80. Разметка страницы — **~86,3 КБ (86 331 Б отдаётся) Б** в
`PAGE_TMPL` (`page_html.h`, лимит `PAGE_CAP` 96 000), остальные ресурсы — в
`assets.h`: `/app.css` 27 437 Б, `/app.js` 56 770 Б, `/history.js` 63 122 Б,
`/control.js` 5 868 Б. Всё это собирается из `firmware/cydv4/web/` скриптом
`build_page.py` (19 плейсхолдеров, лимиты `ASSET_LIMIT` 64 512 и `PAGE_CAP`).

**Сборка потоковая, без `String` в куче.** Значения подстановок (версия, сеть,
RSSI, кВт·ч, рубли, напряжение, мощность, ток, температура, тарифы, дата, час)
лежат в маленьком массиве `PgVal`. Длина ответа считается заранее по шаблону
(`pgOutLen`), тело пишется в сокет одним проходом по `PAGE_TMPL` кусками по
4 КБ (`PAGE_CHUNK`) — шаблон и значения чередуются, `String` не создаётся.
Страница не держится в куче целиком: иначе mbedTLS не хватает непрерывного
блока под TLS к облаку.

| | было | стало |
|---|---|---|
| сборка страницы | 86 мс | **4 мс** |
| память в куче | ≈60 КБ | **0** |
| ответ `/` | 600–950 мс | **124–239 мс** |
| пик ответа | 4,4 с | нет |

Отдача ограничена (`bounded_web_server.h`): общий бюджет **3 с + 50 мс на
КБ** ответа, пауза без прогресса — **1500 мс** для ответов >32 КБ, **600 мс**
для >8 КБ и **150 мс** для мелких API. После подъёма лимитов обычная нагрузка
даёт **20 из 20** загрузок страницы целиком (`pageCut=0`). Патологическая
нагрузка (8 параллельных потоков × 10 загрузок) всё ещё вызывает редкие
обрывы — сервер однопоточный, страница 86 КБ на соединение; это
задокументированное ограничение.

Статика (`/app.css`, `/app.js`, `/history.js`, `/control.js`) отдаётся с
`ETag` и кэшем, версия ресурсов в URL (`?v=…`) меняется с выпуском.
Живые данные страница получает из `/data` (опрос в 3 с, в неактивной вкладке
приостанавливается) и `/measure` (источник/возраст). `/range` и `/history` на
длинных периодах отвечают **202/pending** и готовятся порциями в `loop()`;
страница показывает прогресс и ждёт полный ответ.

| URL | Что |
|---|---|
| `/` | веб-страница (карточки, история, период, климат, события, диагностика) |
| `/app.css`, `/app.js`, `/history.js`, `/control.js` | ресурсы страницы |
| `/data` | текущие значения JSON: `fw`, `build`, `vSeen/pSeen/tSeen`, `stale`, `disp/bright/wake`, `beep/vol`, `led`, счётчики |
| `/measure` | источник/возраст/TTL для V/P/I/T (`source`, `ageSec`, `valid`, `local`, `cloud`) |
| `/storage` | карта: ёмкость, свободно, `writeOk/writeFail/lastWriteAgeSec/lastFailAgeSec/archiveError` |
| `/history?date=YYYY-MM-DD` | почасовая история дня: `kwh`, `p`, `pmax`, `pmaxT`, `pmaxDur`, `v`, `t`, `n`, `vvalid`, `tvalid` |
| `/range?from=&to=` | статистика за период по дням; 202/pending, не больше 31 дня за запрос |
| `/days` | даты, за которые есть данные |
| `/climatehist?from=&to=` | комнатный климат за период: `n`, `tmin/tmax/tavg`, `hmin/hmax/havg`, `pavg`, `partial`, `fileBytes`, `ms` |
| `/climate` | текущий климат, `?data=1` — три ряда `hours/hum/pres`, `?clean=1` — чистка журнала |
| `/weather`, `/forecast` | состояние погоды/прогноза, HTTP-код, ошибка, `ms`, `heap`, `maxAlloc`; `?force=1` — принудительно |
| `/events` | последние переключения реле |
| `/vlog`, `/gost`, `/protect`, `/tuya` | качество энергии, события, уставки защиты, сырые DP |
| `/stage` | этап `loop()`: текущий и прошлый (`st`, `stb`) |
| `/boots` | журнал загрузок (`rr=OTA/POWERON`, `st=…`) |
| `/clog`, `/netdiag`, `/cloudtest` | кольцо облака, сеть DNS/TCP/TLS, один запрос в облако |
| `/full?file=&from=&len=` | сырой файл с карты (в т. ч. `weather.csv`, `boots.log`) |
| `/files` | файлы на карте с размерами |
| `/day`, `/csv` | строки по часам за сегодня / хвост CSV |
| `/tap?x=&y=` | эмуляция касания (нужен `X-Dom-Key`) |
| `/rotate`, `/restorebak`, `/repair` | ротация месяца, откат из `.bak`, починка дублей (`?dedupe=1`) |
| `/disp`, `/beep`, `/sound`, `/sound.html` | подсветка, звуки |
| `/skin`, `/skintest`, `/invert` | темы платы, инверсия |

| `/update`, `/reboot` | OTA и перезагрузка (только с ключом) |
| `/shot?y0=&h=` | снимок TFT (отладочная сборка, только с ключом) |
| `/pagefree` | пустышка: кэша страницы больше нет (зовётся из старых скриптов) |

Всего **53** разных пути (54 обработчика; `/weather` зарегистрирован дважды).

Особенности:

- тело ответа пишется потоково, `TCP_NODELAY`; кэша страницы нет;
- **изменяющие** маршруты требуют `X-Dom-Key`; при отсутствии ключа в прошивке
  управление закрыто с HTTP 503. Ключ — только в установленной конфигурации;
- чтение данных в LAN открыто (у страницы нет пароля) — только доверенная сеть;
- HTTP внутри LAN не шифрует трафик: порт платы не публиковать в интернет;
- опрос `/data` раз в 3 с, история — при смене дня и раз в 2 мин.

## 13. Serial и PC-инструменты

Плата печатает JSON-строки:

```json
{"t":"status","fw":"4.14","name":"CYD-DASH","up":1208,"wifi":true,...}
{"t":"data","v":236,"temp":22.1,"p":152,"e":19.04,"r":true,...}
```

`t` — **тип сообщения**, не температура. Для температуры поле `temp`.

PC-скрипты:

| Скрипт | Что делает |
|---|---|
| `pc/DomMonitor.ps1` + `DomMonitor.exe` | GUI: экран, история, период, климат, архив, терминал, прошивка; лончер без консоли |
| `pc/DomMonitor-run.ps1` | супервизор: держит приложение и Telegram-пинг, мьютекс один экземпляр |
| `pc/DomTelegramPing.ps1` | Telegram-пинг: только чтение состояния платы |
| `pc/ControlAuth.ps1`, `pc/MetricHistory.ps1` | ключ `X-Dom-Key`, история показателей |
| `pc/archive-run.ps1`, `pc/archive-sd.py` | снимок SD и проверяемое восстановление |
| `pc/flash-http.ps1`, `pc/backup-sd.py`, `pc/backup-firmware.py` | OTA с манифестом, бэкапы истории и исходников |
| `pc/diagnose-compact.py` | краткая сводка платы без системного прокси |

`DomMonitor.ps1` — необязательная утилита. Она рассчитана на Windows,
пути и COM-порт задаются в интерфейсе.

## 14. Ограничения

- Wi-Fi только 2,4 ГГц; TX 11 dBm.
- Смены Wi-Fi с экрана нет: сеть задаётся в `secrets.h` или командой
  `WIFISET` по serial (её отправляет мастер настройки).
- Нет отдельного DP мощности; локальный DP 6 может отставать — это видно по
  `source`/`ageSec` в `/measure`.
- Чтение данных в LAN без пароля; **изменяющие** маршруты закрыты `X-Dom-Key`.
  HTTP внутри LAN не шифрует трафик — порт платы не публиковать в интернет.
- ~~Нет OTA~~ — с 4.11.0 работает (`min_spiffs`, два слота, `rr=OTA`),
  с 4.14 — только из приложения, с манифестом и проверкой сборки.
- **TLS облака/погоды/прогноза по-прежнему в `loop()`** — всплески
  1,5–3 с; перенос в отдельную задачу не сделан.
- **Редкие обрывы больших ответов** под патологической нагрузкой;
  обычная нагрузка — 20 из 20 загрузок целиком.
- История не пишется без времени и без напряжения.
- Калибровка тача — только serial.
- Облако Tuya хранит историю 7 суток: `GAPFILL` старше недели не заполнит.
- История климата для `/climatehist` — из хвоста `/climate.csv` (до 400 дней);
  при `partial:true` старые дни могут не попасть в ответ.
- Telegram-пинг работает только при включённом ПК и доступном Telegram и
  умеет только читать.
- Причина паники 16.11 не доказана; `/shot` в обычной сборке выключен —
  диагностика через `/stage` и `/boots.log`.
- `WebServer`/`WiFi` требуют ядра `esp32:esp32` 2.0.9, не 3.x.
