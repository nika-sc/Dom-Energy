## 1. Что делает устройство

Одна плата ESP32-2432S028 (CYD) раз в ~15 секунд читает реле Tuya по
локальной сети, раз в 30 секунд пишет строку истории на microSD, показывает
данные на экране 240×320 и отдаёт веб-страницу в локальной сети.

```
┌──────────────┐    Wi-Fi 2,4 ГГц     ┌─────────────────────────────┐
│ Реле Tuya    │◀────────────────────▶│ ESP32-2432S028 (CYD)        │
│ 220 В        │  TCP 6668, Tuya 3.5  │                             │
│ DP 1/6/16/101│                      │  экран ILI9341 240×320      │
└──────────────┘                      │  тач XPT2046                │
                                      │  microSD /energy.csv        │
┌──────────────┐    HTTPS (интернет)  │  WebServer :80              │
│ Tuya Cloud   │◀────────────────────▶│                             │
└──────────────┘                      └──────────┬──────────────────┘
                                                 │ Wi-Fi LAN
┌──────────────┐    HTTP (интернет)              ▼
│ OpenWeatherMap      │◀────────────────────  ┌─────────────────────┐
└──────────────┘                       │ Браузер телефона/ПК │
                                       └─────────────────────┘
┌──────────────┐    HTTP (LAN, опция)
│ PC API :8090 │◀──────────────────────  плата (температура,
└──────────────┘                          энергия, сверка)
```

Ключевой принцип: **локальные данные (реле, карта, экран) работают без
интернета**. Интернет нужен только для облака Tuya (мощность/история),
погоды и, опционально, PC API.

## 4. Запуск

```
setup()
  ├─ Serial 115200
  ├─ подсветка (GPIO 21), RGB LED
  ├─ тач: tpInit(), loadCal() из NVS
  ├─ Wi-Fi: loadWifi() из NVS, иначе secrets.h
  ├─ TFT: tft.init(), rotation 0, заставка
  ├─ connectWifi(25 с)
  ├─ configTime(UTC+3), ждём NTP до 20 с
  │    └─ нет NTP → restoreClock() из NVS
  ├─ SD: initSD(), initHistoryMonth()
  ├─ loadToday(), loadPeriods(), loadHistDay()
  ├─ seedStatsFromSd() — мин/макс за сегодня
  ├─ tuyaQuery(), cloudStatus(), updateToday()
  ├─ fetchFromApi(), fetchWeather()
  ├─ drawScreen()
  └─ webSetup()
```

Если Wi-Fi нет, плата всё равно запускается: экран, карта и serial работают,
но новые данные с реле не приходят. На экране — «НЕТ ДАННЫХ»/последнее.

## 5. Главный цикл

`loop()` — кооперативный, без RTOS-задач. Тяжёлые операции разбиты на шаги,
чтобы тач не «умирал».

```
loop()
  ├─ handleTouch()                  всегда первым
  ├─ histTick()                     дозаполнение истории (шаг за проход)
  ├─ writeSd()                      не чаще 30 с
  ├─ netOnline()                    проверка интернета раз в 30 с
  ├─ updateToday()                  раз в 5 с
  ├─ updatePeriods()                раз в 60 с
  ├─ seedStatsFromSd()              пока не получится
  ├─ netStep 1..4                   одна сетевая операция за проход:
  │    1) tuyaQuery()               локальное реле
  │    2) cloudStatus()             облако, раз в 60 с
  │    3) fetchFromApi()            PC API, опция
  │    4) pushHistory(), sendJsonData()
  ├─ weather                        раз в 10 мин (нет данных — раз в 60 с)
  ├─ redraw                         по сигнатуре, не чаще 2 мин
  └─ serial-команды
```

Почему так: HTTP/облако могут занимать секунды. Если делать их подряд,
тач и перерисовка стоят. Между шагами вызывается `handleTouch()`.

## 7. Tuya local: протокол 3.5

Реле слушает TCP **6668**. Кадр:

```
0x6699 | 0x0000 | seq(4) | cmd(4) | len(4) | IV(12) + AES-GCM + tag(16) | 0x00009966
```

- ключ шифрования — `LOCAL_KEY` из `secrets.h` (16 байт);
- согласование: cmd 3 → 4 → 5, session key = AES-GCM(local_key, ...);
- запрос данных: cmd 16, ответ — `retcode(4) + JSON{"dps":...}`;
- первые 4 байта ответа — **retcode**, а не JSON.

Разбор DP:

```
DP 1   = 1904        → 19.04 кВт·ч
DP 6   = base64(8)   → word0/10 = В, word3 = Вт, байты 2..4 = мА
DP 16  = true/false  → реле
DP 101 = 221         → 22.1 °C
```

## 8. Tuya cloud: HTTPS и подпись

```
stringToSign = method \n sha256(body) \n \n path
sign         = HMAC-SHA256(secret, clientId + token + t + nonce + stringToSign)
```

- host `openapi.tuyaeu.com`, HTTPS 443, `setInsecure()` (без проверки
  сертификата — на ESP32 это обычная практика, но не идеал);
- токен живёт ~15 минут, кэшируется в RAM;
- статус запрашивается раз в 60 с и только если локальные данные старше 30 с;
- облако даёт `phase_a` — самая свежая мощность/напряжение/ток;
- история за пропущенные часы — по 100 записей, шагами, без блокировки тача.

## 9. Расчёты

### «Сегодня»

`myTodayKwh` = прирост счётчика от `dayStartKwh` (или сумма интервалов из
CSV, если карта доступна). Стоимость — по тарифу часа:

```
06:00–23:00 → TARIFF_DAY   (8.39 ₽/кВт·ч в примере)
23:00–06:00 → TARIFF_NIGHT (4.49 ₽/кВт·ч в примере)
```

Тарифы — константы в начале `.ino`; при публикации это **пример**, а не
«правильные» цены.

### «Вчера» и «месяц»

- вчера: `scanSdRange()` по CSV; если пусто — облако (`cloudDayStart`);
- месяц: база на первое число из облака/карты, дальше прирост счётчика;
- стоимость месяца — по `periodTariff()` (90 % день / 10 % ночь), потому
  что суточный профиль 7/24 ночи не отражает реальное потребление.

### Прогноз

`projKwh = myTodayKwh * 24 / elapsed_hours` (не меньше уже съеденного).
`projCost = projKwh * средний_факт_тариф`.

### Мощность

Мгновенная — из `phase_a`; средняя — по часовым средним, текущий неполный
час не учитывается; пик — максимум часовых пиков (или живой максимум).

**Пики по часам.** Для каждого часа с данными `/history` отдаёт:

- `pmax` — максимальная мощность в часе (из записей каждые 30 с);
- `pmaxT` — время этой записи, `ЧЧ:ММ` (у старых часов без минуты — `null`);
- `pmaxDur` — сколько **секунд** час был не ниже 80 % от `pmax`.

Длительность считается по гистограмме мощности часа (`gPkHist`): секунды
раскладываются по корзинам (100 Вт до 2 кВт, дальше 500 Вт / 1 кВт / 10 кВт+),
затем складываются все корзины от порога 80 % пика и выше (`pkDurSec`).
Строка CSV даёт 30 секунд, поэтому разрешение длительности — 30 с. На экране
и странице секунды показываются минутами (`pmaxDur / 60`, минимум 1 мин).

## 10. SD: формат и жизненный цикл

```
/energy.csv                 текущий месяц
/energy-YYYY-MM.csv         архивы прошлых месяцев
```

Строка:

```csv
2026-10-30 14:33:07,236,152.0,19.04,1,10.39,22.1
```

Правила:

- не чаще 30 с;
- только при `voltage ≥ 50`, `energy > 0`, валидном времени;
- `cost` — накопленная стоимость с начала месяца;
- `temp` может быть пустым, если датчик ещё не ответил;
- при смене месяца файл переименовывается, новый начинается с заголовка;
- чтение — блоками 512 байт, с `esp_task_wdt_reset()`;
- `/full` умеет отдавать диапазон `from`/`len`, чтобы не тянуть мегабайты.

Ёмкость: ~2880 строк/сутки × ~55 байт ≈ 160 КБ/сутки, ~5 МБ/месяц.
Карта 8–32 ГБ подходит с запасом.

Экраны:

| № | Экран | Что |
|---|---|---|
| 0 | ГЛАВНЫЙ | 5 карточек: напряжение, температура, мощность, итоги, погода |
| 1 | НАПРЯЖЕНИЕ | мин/сред/макс, вне нормы, график по часам |
| 2 | ТЕМПЕРАТУРА | корпус реле, макс/сред/мин, график |
| 3 | МОЩНОСТЬ | мгновенная, средняя, пик, ток, график |
| 4 | ИТОГИ | сегодня/вчера/месяц, тариф, день/ночь, прогноз |
| 5 | ПОГОДА | температура, осадки, ветер, влажность, источник |

Экран «СТОРОЖ» (6) в коде есть, но `wdTick()` отключён и в интерфейс не
попадёт: `WD_UI 0`. Экрана «НАСТРОЙКИ» нет.

Тач:

- 5 прямоугольных зон на главном экране, допуск 10 px;
- в окнах — верхняя полоса «НАЗАД», стрелки ‹ › и дата в строке графика;
- нажатие на столбик графика выбирает час;
- калибровка — `CALTOUCH` по serial, 4 угла, NVS `touchcal`.

Перерисовка:

- главный — по сигнатуре, не чаще 2 мин; полная раз в 5 мин;
- окна — точечно, график раз в 5 мин;
- статус-бар — раз в 60 с.

Индикация и звук (всё — NVS и команды):

| Что | Пины | Хранение | Логика |
|---|---|---|---|
| Подсветка | GPIO 21, ШИМ 5 кГц / 8 бит | NVS `disp`: `bright`, `touch` | `0` — погашена; касание при погашенном экране поднимает яркость на 20 с |
| Светодиод | 4 (R), 16 (G), 17 (B), активный низкий, ШИМ | — | приоритет: красный > оранжевый > жёлтый > зелёный; тусклый зелёный = экран погашен |
| Динамик | GPIO 26, ШИМ-тон (канал 1) | NVS `beep`: `on`, `vol`, `touch`, `hour` | по умолчанию выключен; тревоги по напряжению (207–253 В, 10 с) и температуре (> 55 °C) |

Приоритет светодиода считается в `ledWant()` раз в цикл: нет Wi-Fi или две
неудачи реле подряд — красный; нет карты или две ошибки записи — оранжевый
(мигает 1 Гц); нет интернета или три отказа облака — жёлтый; иначе зелёный,
а при погашенной подсветке — тусклый зелёный (20 %).

## 12. Веб-страница

`WebServer` на порту 80. Страница ~≈60 КБ (30 122 Б, предел ответа
`PAGE_CAP` 32 000) лежит в `PAGE_TMPL` (PROGMEM), собирается из
`web/page.html` скриптом `web/build_page.py`.

**Сборка потоковая, без `String` в куче.** Значения подстановок (версия, сеть,
RSSI, кВт·ч, рубли, напряжение, мощность, ток, температура, тарифы, дата, час)
лежат в маленьком массиве `PgVal`: 22 записи по ~48 байт — тег, длина,
значение до 40 символов. Длина ответа считается заранее по шаблону
(`pgOutLen`): длина PROGMEM минус теги плюс значения. Тело пишется в сокет
одним проходом по `PAGE_TMPL` кусками по 4 КБ (`PAGE_CHUNK`) — куски
шаблона и значения чередуются, `String` не создаётся вовсе.

| | было | стало |
|---|---|---|
| сборка страницы | 86 мс | **4 мс** |
| память в куче | ≈60 КБ | **0** |
| ответ `/` | 600–950 мс | **124–239 мс** |
| пик ответа | 4,4 с | нет |

Почему это не косметика: ≈60 КБ, занятые страницей, не давали mbedTLS взять
16-КБ буферы, и TLS к облаку падал с `SSL - Memory allocation failed` —
напряжение «застывало» на часы. Поэтому кэш страницы (`sPage`, TTL 3 с)
убран совсем: `pageCacheFree()` оставлена пустой заглушкой, её по-прежнему
зовут `cloudCall` и `/pagefree`. Подробнее — [PITFALLS.md](PITFALLS.md).

Отдача ограничена: бюджет `PAGE_SEND_BUDGET` 4 с на весь ответ и сторож
`PAGE_SEND_STALL` 0,8 с «нет прогресса». Раньше при `c.write()==0` и
`c.connected()==true` цикл ждал страховку 20 000 мс — отсюда был затык
`loopMaxAll` 19 174 мс.

| URL | Что |
|---|---|
| `/` | страница (светлая, графики) |
| `/data` | текущие значения JSON, в том числе `disp/bright/wake/dtouch`, `beep/vol`, `led` |
| `/history?date=YYYY-MM-DD` | почасовая история за день: `kwh`, `p`, `pmax`, `pmaxT`, `pmaxDur`, `v`, `t`, `n` |
| `/days` | даты, за которые есть данные |
| `/events` | последние переключения реле |
| `/full?file=&from=&len=` | сырой файл с карты (по умолчанию CSV) |

| `/gapfill/status` | прогресс GAPFILL |

Особенности:

- страница собирается потоково, отдаётся кусками по 4 КБ с `TCP_NODELAY`;
- кэша страницы нет: память в куче не занимается, `pageCacheFree()` — пустышка;
- отдача ограничена бюджетом 4 с и сторожем «нет прогресса» 0,8 с;
- `Cache-Control: no-store`;
- опрос `/data` каждые 5 с, история — при смене дня и раз в 2 мин;
- **аутентификации нет** — только доверенная LAN.

## 13. Serial и PC-инструменты

Плата печатает JSON-строки:

```json
{"t":"status","fw":"4.13","name":"CYD-DASH","up":1208,"wifi":true,...}
{"t":"data","v":236,"temp":22.1,"p":152,"e":19.04,"r":true,...}
```

`t` — **тип сообщения**, не температура. Для температуры поле `temp`.

PC-скрипты:

| Скрипт | Что делает |
|---|---|
| `pc/backup-sd.py` | читает `/files` и `/full`, пишет `energy-latest.csv` |
| `pc/backup-firmware.py` | архив исходников с sha256, без `secrets.h` |
| `pc/DomMonitor.ps1` | GUI: serial + HTTP, сборка/прошивка, журнал |

`DomMonitor.ps1` — необязательная утилита. Она рассчитана на Windows,
пути и COM-порт задаются в интерфейсе.

## 14. Ограничения

- Wi-Fi только 2,4 ГГц; TX 11 dBm.
- Нет экрана настроек и смены Wi-Fi с экрана.
- Нет отдельного DP мощности; локальный DP 6 может отставать.
- Веб-страница без пароля.
- ~~Нет OTA~~ — с 4.11.0 работает: `min_spiffs`, два слота, обновление по Wi-Fi (`rr=OTA` в `boots.log`).
- История не пишется без времени и без напряжения.
- Калибровка тача — только serial.
- `WebServer`/`WiFi` требуют ядра `esp32:esp32` 2.0.9, не 3.x.
