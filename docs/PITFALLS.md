## 1. Плата не подключается к Wi-Fi

### Симптомы

```
WiFi.status() == 6   // отключено
WiFi.status() == 4   // отказ
WiFi.status() == 1   // нет сети
```

Плата **видит** сеть при сканировании (`-52…-68 dBm`), но роутер не пускает.
В журнале роутера может не быть даже попытки подключения.

### Причина

Мощность передатчика 20 dBm перекачивает усилитель платы. Приём работает,
передача — нет. Это не антенна и не пароль.

### Решение

В прошивке уже стоит:

```cpp
WiFi.setTxPower(WIFI_POWER_11dBm);   // не 19.5 и не 20
```

Если меняли — верните 11 dBm. На этой мощности плата подключается с первой
попытки. Если роутер уже внёс MAC в бан-лист, перезагрузка платы не поможет:
нужно перезагрузить роутер или перезапустить радио.

## 2. Wi-Fi берётся из NVS, а не только из `secrets.h`

### Симптом

Заполнили `WIFI_SSID` / `WIFI_PASS`, прошили, а плата упорно подключается
к старой сети (или не подключается вовсе).

### Причина

`loadWifi()` сначала читает namespace `wifi` из NVS:

```cpp
gSsid = p.getString("ssid", DEF_SSID);
gPass = p.getString("pass", DEF_PASS);
```

`DEF_SSID` — значение из `secrets.h`, но только **значение по умолчанию**.
Если в NVS уже лежат старые `ssid`/`pass` (от предыдущей прошивки), они
побеждают.

### Решение

- На **чистой** плате NVS пуст — работает `secrets.h`.
- На **перепрошитой** — сотрите NVS (калибровка тача тоже сбросится):

```powershell
esptool --port COM5 erase_region 0x9000 0x5000
```

- Или полный `erase_flash` (см. [RESTORE.md](../RESTORE.md)).
- Смены Wi-Fi с экрана нет и в 4.4: `saveWifi()` вызывается только из
  `WIFISET` (serial или `/wifiset`). Не ищите экран «НАСТРОЙКИ» — его нет.

## 3. Tuya 3.5: retcode 4 байта

### Симптомы

- согласование сессии не проходит;
- «HMAC не совпал — неверный ключ», хотя ключ точно правильный;
- если пропустить проверку HMAC — JSON пустой.

### Причина

В ответах **от устройства** первые 4 байта расшифрованного payload — это
`retcode`, а не данные.

```
было (неправильно):  nonce = payload[0:16],   HMAC = payload[16:48]
надо:                retcode = payload[0:4],
                     nonce   = payload[4:20],
                     HMAC    = payload[20:52]
```

Для данных: `json = payload + 4`, а не `payload`.

### Проверка

Длина payload при согласовании — **52 байта** (4 + 16 + 32), а не 48.
В коде это `parseFrame()` и `tuyaQuery()`; retcode проверяется до разбора.

## 4. DP 101 — это температура, а не напряжение

### Симптом

«Напряжение» показывает 221 В, хотя в сети 236 В. Значение стоит как вкопанное
и не скачет.

### Причина

DP 101 у этого реле — `temp_current`, десятые доли градуса. 221 = 22.1 °C.
Настоящее напряжение и мощность лежат в DP 6 (`phase_a`, base64).

### Как проверить у себя

Напряжение сети **всегда** гуляет на 1–3 В за минуту, температура — нет.
Если число не двигается, а счётчик растёт — это температура.

### Правильная расшифровка

| DP | Что | Формула |
|---|---|---|
| 1 | накопленная энергия | `/ 100` → кВт·ч |
| 6 | `phase_a`, base64 8 байт | word0 / 10 → В; word3 → Вт; байты 2–4 → мА |
| 16 | реле | bool |
| 101 | температура | `/ 10` → °C |

В коде: `parsePhase()` для DP 6, `t10 / 10.0f` для DP 101.

## 5. Локальный DP 6 устаревает

### Симптом

Плата показывает 19 Вт, а облако в ту же минуту — 145 Вт. Или наоборот:
значение «залипло» на несколько минут.

### Причина

Локальный DP 6 приходит не на каждый запрос и может отдавать кэш реле.
Облачный `phase_a` свежее (обновляется примерно раз в 16 с), но требует
интернета.

### Решение в прошивке

- локальный запрос — раз в ~15 с, одна попытка, короткий таймаут;
- облако — раз в 60 с, и только если локальные данные старше 30 с;
- `fetchFromApi()` (ПК) **не берёт** напряжение и мощность: только
  температуру и энергию, потому что локальный DP 6 там тоже устаревший.

Вывод: без интернета мощность может отставать. Это ограничение железа,
а не «баг отображения».

## 6. Мощность без отдельного DP и две шкалы

### Симптом

На графике мощности средняя 150 Вт выглядит нулём, а пик 900 Вт — огромным.

### Причина

У реле нет отдельной точки «мгновенная мощность». В облаке мощность берётся
из `phase_a`, локально — из DP 6 (когда он свежий). На графике средняя и пик
имеют разный масштаб: 150 и 900 Вт на одной шкале 0–1000 Вт не читаются.

### Решение

Страница показывает **две шкалы**: сверху средняя (0–200 Вт), снизу пик
(0–900 Вт). Так видно и «фон», и включение перфоратора. См.
[`power_before_after_390.png`](screenshots/web/05-before-after.png).

Если мощность не приходит вообще, смотрите интернет и облако Tuya: локальный
DP 6 приходит не всегда.

## 7. История пишется не всегда и не чаще 30 с

### Симптом

В `/energy.csv` дыры, либо, наоборот, строки с `voltage=0`.

### Причина и решение

`writeSd()` намеренно не пишет строку, если:

- напряжение < 50 В (датчик ещё не проснулся / нет сети);
- счётчик ≤ 0;
- нет валидного времени;
- прошло меньше 30 с с последней записи;
- идёт дозаполнение вчерашнего дня (чтобы не нарушить порядок дат).

Раньше писались строки с `v=0`, и они ломали мин/среднее. Теперь лучше
честный пропуск, чем нуль. Норма — **113–120 строк в час** (раз в 30 с),
около 2880 в сутки.

## 8. Файл должен быть в хронологическом порядке

### Симптом

После ручного восстановления истории графики пустые, `/history` за день
показывает не всё, `/day` врёт.

### Причина

Все читатели (`findDayStartOffset`, `/day`, `seedStatsFromSd`) ищут
сегодняшние строки **с конца файла**. Если вчерашние строки дописаны после
сегодняшних, поиск ломается.

### Решение

- Восстанавливать историю только на **пустую** карту или в конец файла,
  соблюдая даты.
- В прошивке `writeSd()` придерживается на время `histTick()`, а вчерашние
  строки дописываются только пока сегодняшних ещё нет.
- `IMP` открывает файл в `FILE_APPEND` — он не сортирует. Если в файле уже
  есть сегодняшние строки, сначала сделайте бэкап и слейте файлы (merge)
  в PC-скрипте.

## 9. Нужен `PartitionScheme=min_spiffs`

### Симптом

```
Sketch too big; see ... for tips on reducing it.
```

### Причина

Прошивка — около **1,09 МБ**. В стандартной схеме `default` раздел приложения
1,3 МБ: занято ~87 %, запаса почти нет. В `min_spiffs` раздел 3 МБ,
занято 36 %.

### Решение

Всегда собирать с:

```
esp32:esp32:esp32:PartitionScheme=min_spiffs
```

Не «default», не `min_spiffs`. Подробности — в [BUILD.md](../BUILD.md).

## 10. `User_Setup.h` лежит вне скетча

### Симптом

Прошивка собирается и заливается, но экран чёрный (или белый), подсветка
может гореть.

### Причина

`TFT_eSPI` читает настройки пинов и драйвера из своей библиотеки, а не из
папки скетча:

```
%USERPROFILE%\Documents\Arduino\libraries\TFT_eSPI\User_Setup.h
```

Без правильного файла библиотека собирает «generic» конфигурацию.

### Решение

Скопировать [`firmware/hw/User_Setup.h`](../firmware/hw/User_Setup.h) поверх
файла в библиотеке. Не держите два разных `User_Setup.h` в разных местах.
После замены — полная пересборка (clean build), иначе старый объектный файл
останется.

## 11. Тач калибруется только по serial

### Симптом

Нажимаешь на карточку — открывается соседняя. Или стрелки не реагируют.

### Причина

Калибровка — четыре угла, а не два. Заводские значения могут не подходить
конкретной плате. С экрана калибровку запустить нельзя: экрана настроек нет.

### Решение

1. Подключить USB.
2. Открыть монитор порта на **115200**.
3. Команда `CALTOUCH`.
4. Нажать по очереди четыре мишени по углам (на экране «УГОЛ 1 ИЗ 4»).
5. Проверить `CAL` (текущие значения), при необходимости `CALRESET`.

Значения хранятся в NVS (`touchcal`) и переживают перезагрузку.
`CALRESET` стирает их и перезагружает плату.

## 12. Raw-строка и плейсхолдеры

### Симптом

После правки `web/page.html` и запуска `python web/build_page.py` скетч
не собирается или страница пустая.

### Причина

Страница вшита в `.ino` как raw-строка:

```cpp
static const char PAGE_TMPL[] PROGMEM = R"HTML(
...
)HTML";
```

Если в HTML встретится `)HTML"`, raw-строка закроется раньше времени.
`build_page.py` это проверяет и падает с сообщением.

### Решение

- Не писать `)HTML"` в `page.html`.
- Запускать сборку страницы **из папки `firmware/cydv4`**:
  `python web/build_page.py`.
- Скрипт проверяет 19 плейсхолдера (`__FW__`, `__MV__`, …). Если добавили
  новый — добавьте его в `PLACEHOLDERS`, иначе сборка остановится.
- После сборки коммитить и `page.html`, и изменённый `.ino`.

## 13. Перерисовка по сигнатуре

### Симптом

Экран мерцает, тач «залипает», плата греется.

### Причина

Полная заливка 240×320 по SPI — это ~139 КБ на кадр. Если делать её на
каждое обновление напряжения, цикл не успевает читать тач.

### Решение

- Главный экран перерисовывается по **сигнатуре** видимых данных, не чаще
  раза в 2 минуты; полная — раз в 5 минут.
- В окнах — точечное обновление цифр; график — раз в 5 минут.
- Статус-бар (сеть/SD/RSSI) — отдельно, раз в 60 с.
- Не вызывайте `drawScreen()` вручную в цикле без необходимости.

## 14. Время: NTP или NVS

### Симптом

После включения без интернета история не пишется, часы показывают `--:--`.

### Причина

У ESP32 нет батарейного RTC. Время берётся из NTP; если NTP не ответил,
прошивка пытается восстановить последнее сохранённое время из NVS
(`restoreClock()`).

### Решение

- При первом запуске дайте плате интернет на 20–30 с, чтобы прошёл NTP.
- Без интернета время восстановится из NVS, но будет «плавать» на минуты.
- Если время не восстановилось, `writeSd()` не пишет строки — это защита,
  а не поломка.
- Проверка: команда `STATUS` / `DIAG` в serial, поля `now`, `sdRows`.

## 15. Страница в куче ломает TLS

### Симптом

В serial: `SSL - Memory allocation failed`. Напряжение и мощность «застывают»
на часы, хотя Wi-Fi есть и `/data` отвечает. Стоит открыть страницу в
браузере — облако отваливается.

### Причина

Страница ~≈60 КБ собиралась в `String`: копия шаблона (≈60 КБ) + 22
`String::replace`. Эта память нужна mbedTLS: для TLS-сессии ему требуются
буферы по 16 КБ, а в куче их уже нет. Кэш страницы (TTL 3 с) держал ≈60 КБ
и между запросами — TLS не проходил совсем.

### Решение

- значения подстановок — в массиве `PgVal` (22 × ~48 Б), без `String`;
- длина ответа считается заранее по шаблону (`pgOutLen`), тело пишется в
  сокет одним проходом из `PAGE_TMPL` (PROGMEM) кусками по 4 КБ;
- кэш страницы убран совсем: `pageCacheFree()` — пустая заглушка;
- сборка 4 мс вместо 86, куча — 0 байт.

### Проверка

`/data` → `pageMs` ~4 при `pageN` > 0, `pageSend` 120–240. Десять загрузок
страницы подряд: `heap` не падает (Δ316 Б — фрагментация, не утечка).
`/cloudtest` проходит, `cFail` не растёт.

## 16. 20-секундный затык в отдаче

### Симптом

`/data` показывает `blk=web`, `blkMs` ~19 000, `loopMaxAll` 19 174 мс.
Плата замирает на 19 секунд: не реагирует на тач, не опрашивает реле,
страница не догружается.

### Причина

Клиент перестал читать (закрыли вкладку, моргнул Wi-Fi): `c.write()`
возвращает 0, а `c.connected()` ещё `true`. Старый цикл отдачи в этом
случае крутился до страховки 20 000 мс, держа `loop()`.

### Решение

- бюджет на весь ответ — `PAGE_SEND_BUDGET` 4 с;
- сторож «нет прогресса» — `PAGE_SEND_STALL` 0,8 с: `write()` не
  продвигается — клиент считается мёртвым, отдача рвётся;
- счётчик обрывов — `pageCut` в `/data`;
- `loopMaxAll` 19 174 → 3 346 мс.

### Проверка

Открыть страницу и закрыть вкладку на середине: в serial
`веб: / отдача оборвана на N из ≈60000 байт`, `pageCut` растёт,
`loopMaxAll` — нет.

## 17. Скорость 921600 и ядро 2.0.9

### Симптом

```
A fatal error occurred: Failed to connect to ESP32: Timed out waiting for packet header
```

или сборка падает на несовместимом API.

### Причина

- На 115200 бывают срывы; для CYD проверенная скорость — **921600**.
- Ядро `esp32:esp32` **3.x** несовместимо с этой прошивкой (другой API
  `WebServer`/`WiFi`). Нужно **2.0.9**.

### Решение

```powershell
arduino-cli core install esp32:esp32@2.0.9
```

Прошивка:

```powershell
arduino-cli upload -p COM5 `
  --fqbn esp32:esp32:esp32:PartitionScheme=min_spiffs `
  --upload-property upload.speed=921600 `
  --input-dir build firmware\cydv4
```

Если порт не открывается — проверьте драйвер USB-UART (CH340/CP210x)
и что плата не в глубоком сне.

## 18. Сторожевой таймер и чтение блоками

### Симптом

Плата перезагружается при чтении `/full` или большой истории.

### Причина

Файл на несколько тысяч строк читается дольше таймаута сторожевого таймера,
если читать `readStringUntil` построчно с `String`.

### Решение

- История читается **блоками по 512 байт** (`dayLoadFromSd`), с
  `esp_task_wdt_reset()` каждые 512 строк.
- `/full` поддерживает диапазон `from`/`len`, чтобы не отдавать мегабайты
  за один запрос.
- Не отключайте watchdog «навсегда»: лучше сбрасывать его в циклах.

## 19. Чего в этой версии нет

- **Экрана «НАСТРОЙКИ» нет.** Wi-Fi — только `secrets.h` (+ NVS).
- **Экрана «СТОРОЖ» нет** в интерфейсе: `wdTick()` отключён, `WD_UI 0`.
  Не ищите его в меню и не добавляйте в README как доступный.
- **Рисования/палитры нет** — старый комментарий в шапке врал.
- **Калибровки с экрана нет** — только `CALTOUCH` по serial.
- **Пароля на веб-странице нет** — не публикуйте порт 80 в интернет.

## 20. Полезные команды serial

| Команда | Что делает |
|---|---|
| `STATUS` | статус: Wi-Fi, IP, Tuya, SD, heap, экран |
| `DIAG` | расширенная диагностика |
| `CSV` | хвост `/energy.csv` |
| `CSVDAY` | строки за сегодня по часам |
| `CSVH` | восстановленные из облака строки |
| `CSVHIST` | принудительно дозаполнить историю из облака |
| `CALTOUCH` | калибровка четырёх углов |
| `CAL` | показать текущие коэффициенты |
| `CALRESET` | сбросить калибровку |
| `RAW` | сырые значения тача |
| `IMP` … `IMPEND` | импорт строк CSV на карту |
| `NET` / `NETOFF` / `NETON` | проверка/отключение интернета |
| `WIFIOFF` / `WIFION` | выключить/включить радио |
| `SHOT 0..6` | снять экран в serial (для скриншотов) |
| `DEMO` | широкие числа в ИТОГАХ для проверки вёрстки |
| `PERIODRESET` | сбросить базы «сегодня/вчера/месяц» |

## 21. Если совсем не работает

Порядок диагностики:

```
1. Плата питается? Подсветка горит? (погашена — не поломка: `DISP` может
   стоять в `OFF`, проверьте командой `DISP` и включите `DISP ON`)
2. COM-порт появляется? Драйвер USB-UART стоит?
3. Serial 115200: что печатает при старте?
4. Wi-Fi: статус, RSSI, IP (команда NET/STATUS)
5. Реле: ping <IP реле>, порт 6668 открыт?
6. SD: gSdOk, gSdRows (команда DIAG)
7. Время: now в /data или STATUS
8. Веб: http://<IP-платы>/data отвечает?
```

Если на каком-то шаге «нет» — дальше не идите, чините его. Большинство
«глюков интерфейса» — это Wi-Fi, время или карта.
