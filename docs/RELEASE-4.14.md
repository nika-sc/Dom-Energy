# Дом — энергия 4.14

**Учёт электроэнергии на ESP32-2432S028 (CYD): реле Tuya, экран 2,8″, история
на microSD, веб-страница в памяти платы и программа для Windows.**

Дата выпуска: **21.11.2026**. Прошлый опубликованный выпуск — 4.13 (11.11.2026).
Прошивка **4.14**, сборка `6fe4b87d3a861ba37f1f`.

> `docs/screenshots/4.14/` (`web/`, `pc/`, `board/`); в тексте ниже указано,

## Что это

Одна плата, одно реле, одна карта памяти. Плата по локальной сети читает
реле Tuya (напряжение, ток, мощность, накопленную энергию, температуру
корпуса), раз в 30 секунд пишет строку истории на microSD, показывает данные
на экране 240×320 и отдаёт веб-страницу прямо из своей flash. Программа для
Windows — необязательный пульт: те же данные крупно, история, отчёты, архив.

Всё основное работает без интернета. Интернет нужен только для облака Tuya
и погоды.

## Главное в 4.14

- **Каждый показатель знает свой источник и возраст.** Новый эндпоинт
  `/measure` отдаёт `source` (`local` / `cloud` / `none`), `ageSec` и
  `ttlSec` для напряжения, мощности, тока и температуры. На странице и в
  приложении видно «локальное реле · 14 с», «облако · N с», «устарело»,
  «нет свежих данных». Не полученное значение больше не выглядит нулём.
- **Честная математика истории.** `null` — это пропуск, а не ноль;
  средняя мощность взвешивается по числу измерений; неполные дни помечаются;
  в истории всегда 24 ячейки, выбирается любая — и пустая тоже.
- **Настоящий комнатный климат за период.** `GET /climatehist?from=&to=`
  отдаёт по дням температуру, влажность и давление из `/climate.csv`.
  Веб и приложение показывают «комнату за период», покрытие «N из M дней»
  и корреляции с расходом — с честной пометкой «связь не означает причину».
- **Период стал рабочим инструментом**: сравнение с предыдущим периодом,
  топ-5 пиков нагрузки, бюджет и прогноз счёта, экспорт CSV с единицами.
- **SD-карта под контролем**: проверка каждой записи, счётчики ошибок в
  `/storage`, починка дублей (`/repair?dedupe=1`), восстановление после
  обрыва питания, ротация без удаления истории. Ежедневный проверяемый
  архив на ПК (`DomEnergy-DailyArchive`, SHA-256 + gzip) и вкладка «Архив»
  в приложении с тестом восстановления.
- **Экран «СОСТОЯНИЕ» на плате** — одним взглядом: реле, Wi-Fi, облако,
  карта, время, возраст данных.
- **Telegram-пинг**: бот отвечает полным состоянием платы на слово «пинг».
  Только чтение, только один личный чат, токен не в репозитории.
- **Единый `DomMonitor.exe` без чёрного консольного окна**, автозапуск через
  задачу планировщика; графики приложения переписаны на .NET Chart.
- **Управление платой закрыто ключом `X-Dom-Key`**, доверенные корни TLS —
  в `trusted_roots.h`, `setInsecure()` не используется.

- Один свёрнутый блок «Подробная статистика и таблица периода»: пресеты,
  свой диапазон, режимы «Часы · Дни · Недели», график с легендой-переключателем,

- Климат и энергия: комната за период, корреляции, таблица по дням.
- События и диагностика; кнопка «Скопировать отчёт» — обезличенный текст

- Панель «Состояние и качество данных»: LAN и WAN отдельно, свежесть
  V/P/I/T, SD-записи, облако.
- Онлайн-мощность обновляется раз в 1,5 с; `/range` и `/history` —
  асинхронные (202/pending с прогрессом).

### Windows-приложение

- Графики на `System.Windows.Forms.DataVisualization.Charting`: энергия
  столбиками, напряжение линией, температура полосой, сравнение с вчера,
  день/ночь, экспорт PNG, переключатель «День · 7 дней · 30 дней».
- История открывается быстро: вчера предзагружается, прошедшие дни
  кэшируются, вместо «нет данных» — «загрузка истории…».
- Вкладки **«Терминал»** (что плата делает сейчас, `/vlog`, `/clog`,

- `DomMonitor.exe` — Windows-GUI-лончер без консоли; супервизор держит

### Telegram-пинг

`pc/DomTelegramPing.ps1` под супервизором слушает Telegram (long-poll).
Напишите «пинг» — придёт состояние: сборка, uptime, память, LAN,
облако, V/P/I/T с возрастом, энергия и деньги, тариф, карта, пропуски,
последняя загрузка.

Ограничения честно: работает **только при включённом ПК** и доступном
Telegram; бот только читает, управляющих команд у него нет; отвечает в один
привязанный личный чат; токен хранится в `%APPDATA%\DomMonitor\`, не в
репозитории.

## Установка и обновление

- **Первая прошивка** — USB: `arduino-cli` + ядро `esp32:esp32@2.0.9`,
  `TFT_eSPI 2.5.44` со своим `User_Setup.h`, `ArduinoJson 7.4.3`,
  `PubSubClient 2.8`; схема разделов `PartitionScheme=min_spiffs`.
  Подробно — `BUILD.md`.
- **Обновление** — только из приложения: вкладка «Прошивка» → «Прошить по
  Wi-Fi» (образ + манифест с SHA-256). Из веб-страницы OTA не делаем
  осознанно: страница живёт на самой плате.
- **Восстановление** — `RESTORE.md`: исходники, `secrets.h`, `User_Setup.h`,
  сборка, восстановление карты и архива.

Требования: ESP32-2432S028 (CYD) с резистивным тачем и слотом microSD,
реле Tuya с измерением мощности, карта microSD FAT32 (класс 10),
Wi-Fi 2,4 ГГц, Windows — для приложения и архива (необязательно).

## Известные ограничения

- **TLS облака и погоды живёт в `loop()`** — всплески цикла 1,5–3 с
  возможны. Перенос TLS в отдельную задачу требует стенда и пока не сделан.
- **Редкие обрывы больших ответов** под патологической нагрузкой
  (8 параллельных потоков загрузки страницы): сервер однопоточный, страница
  86 КБ. Обычная нагрузка — 20 из 20 загрузок целиком; во время TLS-всплесков возможен редкий обрыв.
- **Telegram-пинг** — только при включённом ПК и доступном Telegram.
- **История климата** читается из хвоста `/climate.csv` (до 400 дней);
  при `partial:true` самые старые дни могут не попасть в ответ.
- **Облако Tuya хранит историю 7 суток** — `GAPFILL` старше недели не
  заполнит.
- **Причина паники 16.11 не доказана**; `/shot` в обычной сборке выключен,
  для диагностики используется `/stage` и `/boots.log`.
- **Чтение данных в LAN открыто** — только доверенная сеть, порт платы не
  публиковать в интернет. HTTP внутри LAN не шифрует трафик.
- `history.js` — 63 122 Б при лимите 64 512 Б: новый код в него не кладём.
