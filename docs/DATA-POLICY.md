# Политика данных: что публикуется, а что нет

> Коротко: в репозитории лежит **код и описание**, но не ваши ключи,
> пароли, адреса и история потребления. Всё личное вынесено в
> `firmware/cydv4/secrets.h`, которого в репозитории нет.

## 1. Что публикуется

| Что | Где | Зачем |
|---|---|---|
| Исходный код прошивки | `firmware/cydv4/cydv4.ino` | чтобы собрать и повторить |
| Шрифт и веб-страница | `firmware/cydv4/font5x7.h`, `web/page.html` | часть прошивки |
| Настройка TFT | `firmware/hw/User_Setup.h` | без неё экран не работает |
| Схема данных | `README.md`, этот файл | понять, что и как измеряется |
| Формат строки SD | раздел 3 ниже | совместимость с другими инструментами |
| Скриншоты | `docs/screenshots/` | показать интерфейс |
| Скрипты ПК | `pc/` | бэкап и диагностика |

Скриншоты сделаны на реальном устройстве. На них видны даты, напряжения,
температура и расход за выбранные дни — это **не ключи и не адреса**.
Если вы публикуете форк со своими данными, помните: по графику можно
оценить бытовой профиль. Для полной приватности замените скриншоты своими
или используйте демо-данные.

## 2. Что НЕ публикуется

| Данные | Почему | Где хранится |
|---|---|---|
| Пароль и имя Wi-Fi | доступ в вашу сеть | `secrets.h` |
| Tuya Device ID | идентификатор устройства | `secrets.h` |
| Tuya Local Key | ключ шифрования локального протокола | `secrets.h` |
| Tuya Client ID / Secret | доступ к облаку | `secrets.h` |
| IP реле, платы, ПК | адреса вашей сети | `secrets.h`, `BOARD_URL` |
| Координаты города | указывают на место жительства | `secrets.h` (`WEATHER_LAT/LON`) |
| История потребления | бытовой профиль | `energy.csv` на SD, бэкапы |
| Полный дамп flash / NVS | содержит ключи и калибровку | `flash-dumps/` (в `.gitignore`) |
| Сборки `.bin/.elf/.map` | не нужны для сборки, могут содержать строки | `build/` (в `.gitignore`) |

В `firmware/cydv4/cydv4.ino` этих значений нет. Вместо них — `#include "secrets.h"`.
Шаблон с пустыми значениями: [`firmware/cydv4/secrets.example.h`](../firmware/cydv4/secrets.example.h).

## 3. Формат строки на SD

Файл: `/energy.csv` в корне карты. Заголовок:

```csv
datetime,voltage,power,energy_kwh,relay,cost,temp
2026-10-30 14:33:07,236,152.0,19.04,1,10.39,22.1
```

| Поле | Что означает | Единица |
|---|---|---|
| `datetime` | локальное время платы (NTP или NVS) | `YYYY-MM-DD HH:MM:SS` |
| `voltage` | напряжение в сети | В |
| `power` | мощность через реле на момент записи | Вт |
| `energy_kwh` | **накопленный** счётчик реле | кВт·ч |
| `relay` | состояние реле | `1` — включено, `0` — выключено |
| `cost` | накопленная стоимость с начала месяца | ₽ |
| `temp` | температура **корпуса реле** | °C |

Правила записи:

- не чаще **раза в 30 секунд** (около 2880 строк в сутки);
- строка не пишется, если напряжение < 50 В, счётчик ≤ 0 или нет времени;
- если температура ещё не пришла, седьмое поле остаётся пустым;
- в конце месяца файл переименовывается в `/energy-YYYY-MM.csv`,
  а `/energy.csv` начинается заново с заголовка;
- строки, восстановленные из облака, имеют `energy_kwh=0`, `relay=0`,
  `cost=0.00` — чтобы не задвоить счётчик.

## 4. Что уходит в облако Tuya

Плата обращается к `openapi.tuyaeu.com` (HTTPS), только если есть интернет:

- получает `access_token` по `client_id` + подпись HMAC-SHA256;
- запрашивает состояние устройства (`/v1.0/devices/<device_id>`);
- получает `total_forward_energy`, `phase_a` (напряжение/ток/мощность),
  `temp_current`, `switch`;
- для дозаполнения истории — почасовые записи за пропущенные часы.

В облако уходят: **Device ID, Client ID, подпись запроса, время, токен**.
Пароль Wi-Fi и Local Key в облако не уходят. Облако видит историю
потребления устройства — это его штатная функция, не «утечка» прошивки.

Локальный протокол (TCP 6668) работает **только в вашей сети** и не требует
интернета. Именно он даёт напряжение, счётчик, реле и температуру, когда
внешней сети нет.

## 5. Что уходит в OpenWeatherMap

Два HTTPS-запроса (погода сейчас и прогноз на 48 ч):

```
https://api.openweathermap.org/data/2.5/weather?lat=<широта>&lon=<долгота>&appid=<ключ>&units=metric&lang=ru
https://api.openweathermap.org/data/2.5/forecast?lat=<широта>&lon=<долгота>&appid=<ключ>&units=metric&lang=ru&cnt=10
```

Уходят координаты и ключ OpenWeatherMap. Ни истории, ни Device ID, ни паролей.
Координаты и ключ задаются в `secrets.h` (`WEATHER_LAT` / `WEATHER_LON` / `OWM_KEY`);
в репозитории их нет. Если ключ не заполнен, плата погоду не запрашивает —
экран покажет «НЕТ ДАННЫХ».

## 6. Что остаётся локально

- история на microSD;
- веб-страница платы (`http://<IP-платы>/`) — только в локальной сети;
- serial-порт (USB) — только на вашем компьютере;
- бэкапы `pc/backup-sd.py` — на вашем диске;
- архив прошивок `pc/backup-firmware.py` — на вашем диске/NAS.

## 7. Важно: у веб-страницы нет пароля

Встроенный `WebServer` слушает порт 80 **без аутентификации**. Кто угодно
в вашей локальной сети может открыть страницу и прочитать показания.
Это нормально для домашней сети, но:

- не пробрасывайте порт 80 на роутере в интернет;
- не подключайте плату к гостевой/публичной Wi-Fi без изоляции клиентов;
- если нужен удалённый доступ — только через VPN, не через port forwarding.

## 8. Как настроить свои ключи

```powershell
cd firmware\cydv4
copy secrets.example.h secrets.h
notepad secrets.h
```

Заполните:

```cpp
#define WIFI_SSID      "ваша_сеть"
#define WIFI_PASS      "ваш_пароль"

#define TUYA_DEVICE_ID "..."
#define TUYA_LOCAL_KEY "..."
#define TUYA_CLIENT_ID "..."
#define TUYA_SECRET    "..."

#define RELAY_IP       "192.168.1.25"
#define PC_API_URL     "http://192.168.1.20:8090"

#define OWM_KEY        ""            // ключ OpenWeatherMap, можно пусто
#define WEATHER_LAT    "43.43"
#define WEATHER_LON    "39.92"

#define MQTT_HOST      ""            // пусто = MQTT выключен
```


`secrets.h` уже в `.gitignore`. Проверка перед коммитом:

```powershell
git status --short
git grep -n "WIFI_PASS\|TUYA_SECRET\|LOCAL_KEY" -- . ":(exclude)firmware/cydv4/secrets.example.h"
```

Если в выводе есть реальные значения — не коммитьте.
