# Правила разработки «Дом — энергия»

Документ обязателен для меня и для любого агента, который трогает этот проект.
Он появился после того, как я несколько раз переделывал то, что уже было
утверждено: заставку, шапку, звуки.

## 1. Утверждённое не меняем

Всё, что перечислено в разделе 2 «Реестр утверждённого», считается **принятым**.
Менять это можно **только по прямой явной команде владельца** в текущем сообщении.

- Не «улучшать» попутно: увидел некрасивое — **напиши в отчёте**, не правь.
- Не менять размеры, цвета, тексты, порядок элементов «для единообразия».
- Если правка утверждённого всё же нужна для задачи — сначала **спросить**.

Формулировки владельца, которые считаются разрешением:
«поменяй заставку», «сделай часы меньше», «верни как было».
Формулировки, которые разрешением **не** считаются:
«сделай красиво», «поправь интерфейс», «проверь и исправь».

## 3. Темы браузера и платы — независимы

Выбор темы в браузере **не** меняет тему платы, и наоборот.
Общего состояния нет: браузер хранит свой выбор в `localStorage`, плата — в NVS.

## 4. Звук: предпросмотр = живому звуку

Любой предпросмотр на странице `/sound.html` обязан играть через
`GET /beep?ev=<событие>` — тот же путь, что и живое событие (та же громкость,
те же тихие часы). Предпросмотр «в обход» запрещён: раньше он играл громче,
чем реальный тап.

## 5. Порядок работы

1. Сначала прочитать этот файл и `CHANGELOG.md` (что уже принято).
2. Правки — маленькими шагами, с проверкой на живой плате.
3. Перед релизом — независимый проверяющий агент по чек-листу.
4. В отчёте честно писать, **что изменено и что не тронуто**.

## 6. Что проверять перед словом «готово»

- `GET /data` → `fw` совпадает с ожидаемой версией, `ui` растёт;
- `/skintest?n=0..5` — у каждой темы свой фон и акцент;
- `/beep?ev=touch` → `preset` тот, что задан в настройках;
- `/invert?on=0`, затем `?on=1` — панель меняет «негатив» и возвращается;
- веб: `node --check web/app.js` — без ошибок;
- после перезагрузки платы выбранный скин сохраняется.

## 7. Версии и коммиты

**Версии только минорные: 4.13, 4.14, 4.15.** Патчей (второй точки в номере) нет —
все исправления и мелкие улучшения входят в текущий минорный выпуск.
Меняем `FW_VER` и все упоминания версии в доках **одним** значением.

**Один коммит — один релиз.** В истории репозитория должно быть столько коммитов,
сколько выпусков: переписка, промежуточные «поправил», «ещё раз» — не коммитятся.
Перед релизом рабочее состояние сводится в один коммит:

```
git reset --soft <коммит прошлого релиза>
git add -A            # без -f: секреты и мусор остаются в .gitignore
git commit -m "4.13: <короткое описание выпуска>"
git tag -a v4.13
```

Запрещено: `git add -A -f` (протаскивает `secrets.h`, `shots/`, `*.bak`),
коммиты «по ходу», отдельные коммиты на документацию и скриншоты.
