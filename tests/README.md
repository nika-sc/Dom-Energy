# Тесты платы

> Обновлено 14.11.2026: адрес по умолчанию `http://192.168.1.51`, рабочая версия 4.14. Текущие физические границы теста: V 0–300, T −40…125, P 0–5000, I 0–25; нулевое напряжение при запуске не считается отказом HTTP. Полный перечень регрессий — в конце файла и раздел «План тестирования» (внутренняя документация). `--quick` пропускает сравнение мощности, но всё равно читает полный CSV для целостности/математики. Более ранние примеры номеров версий и границ ниже являются исторической справкой.

`tests/test-board.py` — сквозные проверки живого устройства по HTTP.
Только чтение: тесты не пишут на карту и не переключают реле.

## 1. Что нужно

- плата в той же сети, что и компьютер;
- известен её IP (serial `STATUS` или `NET`, либо экран/роутер);
- прошивка собрана и залита;
- на карте есть история (`/energy.csv`), иначе часть проверок
  предупредит о нехватке данных;
- Python 3.9+; сторонние пакеты **не нужны** (только стандартная библиотека).

## 2. Запуск

```powershell
# из корня репозитория
$env:BOARD_URL = "http://192.168.1.51"   # ваш IP платы
python tests\test-board.py
```

Быстрый режим (без проверки качества мощности):

```powershell
python tests\test-board.py --quick
```

Проверка мощности за всю историю (медленнее):

```powershell
python tests\test-board.py --all-days
```

Тарифы и границы ночи тест читает из `/tariff`, включая журнал действия тарифов.
Полные файлы SD читаются порциями 32 КиБ через `pc/board_http.py`, без блокировки платы большим скачиванием. `HTTP 202` истории означает продолжающийся расчёт; тест ждёт завершения и отвергает `trunc=true`.

Часовой пояс платы (по умолчанию UTC+3), если нужен другой:

```powershell
$env:BOARD_TZ = "3"
```

## 3. Что проверяется

| Группа | Проверки |
|---|---|
| Доступность | `GET /`, `/data`, `/days`, `/history`, `/events`; мусорная дата отклоняется |
| Контракт | в `/data` есть `v`, `temp`, `p`, `amp`, `e`, `r`, `tkwh`, `tcost`, `ykwh`, `ykost`, `mkwh`, `mcost`, `tariff`, `rssi`, `sdRows` |
| Границы | 180–260 В, 15–60 °C, 0–5000 Вт, 0–25 А; счётчик > 0; карта не пуста |
| Целостность | счётчик не убывает; все часы за 2 суток заполнены (норма 113–120 строк/час) |
| Мощность | интеграл мощности сходится со счётчиком (0.75–1.33); нет «застывших» часов |
| Математика | сумма часов = «сегодня»/«вчера»; пик ≥ средняя; стоимость по зонам; прогноз |
| Стабильность | 10 загрузок страницы, 10 запросов `/data`, нет перезагрузки, heap не просел |

Тест мощности — главный: он ловит случай, когда в CSV пишется 19 Вт, а
счётчик за час прибавил 0.32 кВт·ч. Тогда интеграл даёт 0.019 вместо 0.32,
и расхождение видно сразу.

## 4. Вывод и код возврата

```
ГРУППА            ПРОШЛО
доступность       5/5
контракт          8/8
...
ВСЕГО: 42 из 42
```

- `0` — всё прошло (предупреждения не считаются провалом);
- `1` — есть провалы.

Предупреждения (`ВНИМ`) — это, например, одна дырка в истории после
перепрошивки. Они не ломают публикацию, но показывают состояние.

## 5. Если тесты не идут

| Симптом | Что проверить |
|---|---|
| `urlopen error timed out` | IP платы, Wi-Fi, `ping` |
| `Connection refused` | плата не подняла `WebServer`; serial `STATUS` |
| `/data` без полей | старая прошивка; перепрошить 4.4 |
| «строк с датой найдено 0» | карта пуста/не читается; serial `DIAG` |
| «часы заполнены» с дырками | плата стояла/перепрошивалась; это предупреждение |
| «интеграл мощности» врёт | локальный DP 6 устарел; смотреть облако Tuya |

## Регрессионные проверки от 13.11.2026

Из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-protocol.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-windows.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-native-clicks.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-storage.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-history-index.ps1
python tests/review-web.py
python tests/review-ota.py
python tests/review-archive.py
python tests/review-board.py
python tests/review-slow-client.py
python tests/review-live-web.py
python tests/review-range.py
python tests/review-installed.py
python tests/test-board.py
```

`review-protocol.ps1` исполняет извлечённые из прошивки проверки размеров/префиксов в C#-стенде с механической заменой C-типов; GCM заменён заглушкой, криптография этим тестом не проверяется. Проверяются 301 длина, границы терминатора, повреждённые длины/суффикс и NUL-заголовок push Tuya. Повреждённые кадры на реле не отправляются.

Windows-тест извлекает реальные определения функций через AST вместе с параметрами; проверяет начальные нули, неполную историю, повторы, температуры, блокировку файла прогресса и код выхода настоящего дочернего процесса. Для браузерного теста нужны Python Playwright и установленный Edge; данные детерминированы в `web_fixtures.py`. OTA-тест использует только loopback-сервер и тестовый образ.

Браузерный стенд принудительно обрывает два запроса периода (`connectionreset`), затем отвечает 202/pending; успешный график обязан восстановиться. Живой тест пишет сетевые ошибки в журнал и считает только `.history-combined svg`, исключая скрытые SVG подробного отчёта. Полный `test-board.py` по умолчанию сравнивает два последних дня (`BOARD_FRESH_DAYS=1..366`); отсутствие пригодных часов энергии считается предупреждением, а не успехом без проверки.

Транспорт веба ограничивает параллельное чтение двумя запросами до получения тела ответа. Стенд удерживает три чтения конфигурации и проверяет очередь, а также единственную отправку команды `/tap` при сетевом сбросе. OTA-стенд дополнительно возвращает временный 503 до загрузки: контрольное чтение должно восстановиться, POST с образом остаётся ровно один. В настоящей OTA контрольные GET идут напрямую без прокси, с `Connection: close` и ограниченными повторами чтения.

`review-native-clicks.ps1` под Windows PowerShell 5.1 открывает диагностическую форму за границей экрана и вызывает реальные WinForms HitTest/MouseDown для всех 24 часов главного графика и истории. Проверяет также попадание в Gridlines. `review-storage.ps1` исполняет реальную транзакцию ротации с отказами/прерываниями в модели; `review-history-index.ps1` — 100 дат и 300 граничных позиций. `review-archive.py` проверяет 24 месяца, SHA/gzip, порчу, повторное скачивание и побайтовое восстановление. Эти стенды не заменяют физическое извлечение SD или обрыв питания FAT.

`review-range.py` на живой плате намеренно включает сегодня в период, чтобы получить холодный асинхронный расчёт; проверяет 202/pending, доступность `/data`, отсутствие reboot/переключений реле и известные ноябрьские суммы/число строк. `review-installed.py` сравнивает безопасные исходники с локальной папкой проекта (путь задаётся параметром), проверяет Python AST и UTF-8 BOM русских WinForms-модулей. Конфигурационные секреты в отчёт не выводятся.

`review-live-web.py` читает настоящую плату через изолированный Edge: значения выбранных часов, дневная/недельная/месячная навигация, двойной клик и ошибки JavaScript. `local-fallback-check.py --seconds 480` требует освобождённый COM5, временно выключает интернет-API платы через NETOFF и возвращает NETON в finally. Это не отключает WAN у самого реле. Полный перечень испытаний и границы доказательств: раздел «План тестирования» (внутренняя документация).

`review-board.py` читает настоящую плату; дополнительно отправляет пустой OTA-запрос, который должен дать 400, и неавторизованные запросы, которые должны дать 401. Он не загружает образ и не переключает нагрузку. Нужен локальный `control.key`. `review-slow-client.py` сбрасывает только диагностические счётчики времени и проверяет медленного читателя JS. `pc/local-fallback-check.py` временно выключает интернет-API платы через USB (`NETOFF`) и в `finally` возвращает `NETON`; перед ним освободить COM5, после вернуть приложение.

`/full` может отдавать сотни килобайт; на медленной сети тест идёт долго.
Это нормально: таймаут в скрипте — 180 с.


## Проверка облачных данных

`python tests/review-cloud-recovery.py [путь-к-приватному-json]` проверяет синтетические пограничные случаи, формат и монотонность фактических событий Tuya, а также максимальное число записей в любом десятиминутном окне. Это проверка входных данных, не замена тесту прошивки, сетевого соединения и безопасной записи на SD. Приватный JSON в архив передачи не включать.


## GAPFILL: диагностические исходы

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/review-gap-commit.ps1` извлекает тело gfCommit из текущей прошивки и проверяет его ветви на модели файловой системы, включая отсутствие мутаций при пустом облачном ответе и отказ при неправильном итоговом размере. Карту и реле тест не затрагивает; проверку реальной SD и питания он не заменяет.
