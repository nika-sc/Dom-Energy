# DomMonitor.exe — тонкий лончер

`DomMonitor.exe` — это **не сама программа мониторинга**, а маленький запускатор
(≈49 КБ). Он не рисует окон и не висит в трее: его единственная задача — скрыто
запустить `DomMonitor-run.ps1` и сразу выйти. Всё остальное (окно, трей,
настройки, графики) по-прежнему делает PowerShell-скрипт.

Такой подход позволяет получить «один .exe на рабочем столе» без .NET SDK,
без установки чего-либо и без интернета: компилятор C# уже входит в состав
Windows (.NET Framework 4.x).

## Состав

| Файл | Назначение |
|------|------------|
| `DomMonitor.exe` | готовый лончер (Windows GUI, без консоли) |
| `launcher.cs` | исходник лончера (C# 5, WinForms) |
| `app.ico` | иконка (16–256 px), встраивается в .exe |
| `build-exe.ps1` | сборка одной командой через `csc.exe` |
| `DomMonitor-run.ps1` | супервизор: запускает и перезапускает программу |
| `DomMonitor.ps1` | сама программа (WinForms, трей, настройки) |

## Требования

- Windows 10/11 (x64 или x86);
- .NET Framework 4.8 — встроен в Windows 10/11, отдельно ставить не нужно;
- Windows PowerShell 5.1 (`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`);
- интернет и .NET SDK **не нужны**.

## Как собрать

Из папки `pc`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-exe.ps1
```

Скрипт сам находит компилятор:

```
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe
```

и вызывает его с параметрами:

```
/nologo /target:winexe /platform:anycpu /optimize+
/win32icon:app.ico /out:DomMonitor.exe launcher.cs
```

После сборки печатается путь, размер и подсистема PE (должна быть
`Windows GUI (2)` — это и означает «без консольного окна»).

## Откуда берётся .ps1

Лончер ищет `DomMonitor-run.ps1` в двух местах, в таком порядке:

1. **рядом с `DomMonitor.exe`** — папка, из которой запущен .exe;
2. `%LOCALAPPDATA%\DomMonitor\DomMonitor-run.ps1`
   (обычно `C:\Users\<имя>\AppData\Local\DomMonitor\`).

Если файл не найден, показывается окно с понятным текстом и списком
проверенных путей. В режиме `--dry-run` вместо окна печатаются эти пути,
код возврата — `2`.

Сам `DomMonitor-run.ps1` ищет `DomMonitor.ps1` рядом с собой
(`$PSScriptRoot`). Поэтому минимальный комплект рядом с .exe:

```
DomMonitor.exe
DomMonitor-run.ps1
DomMonitor.ps1
```

Можно держать скрипты и в `%LOCALAPPDATA%\DomMonitor` — тогда .exe может лежать
где угодно (например, на рабочем столе).

## Как запускать

- **Обычный запуск:** двойной клик по `DomMonitor.exe` (или просто
  `DomMonitor.exe`). Лончер скрыто стартует супервизор и завершается.
  Повторный запуск безопасен: супервизор использует глобальный мьютекс
  `Global\DomMonitorSupervisor_SingleInstance`, второй экземпляр молча выходит.
- **Проверка пути, ничего не запуская:**

  ```powershell
  .\DomMonitor.exe --dry-run
  ```

  Так как .exe — GUI-приложение, консольный хост не ждёт его завершения.
  Чтобы гарантированно получить вывод и код возврата, используйте:

  ```powershell
  .\DomMonitor.exe --dry-run | Out-String
  (Start-Process .\DomMonitor.exe -ArgumentList '--dry-run' -Wait -PassThru).ExitCode
  ```

  Пример вывода:

  ```
  D:\DSH-Workspace\GITHUB-REPO\dom-energy\pc\DomMonitor-run.ps1
  ```

- **Коды возврата:** `0` — успех (или путь найден в `--dry-run`);
  `1` — не удалось запустить PowerShell; `2` — скрипт не найден.

Остановка — штатная, через меню в трее самой программы. Отдельного
«выключить лончер» не нужно: он уже вышел.

## Что проверено при сборке

- `DomMonitor.exe --dry-run` печатает полный путь к `DomMonitor-run.ps1`, код `0`;
- запуск без аргументов создаёт скрытый процесс `powershell.exe` с командной
  строкой `-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "<путь>"`,
  процесс живёт (это и есть супервизор), видимого окна у него нет
  (`MainWindowHandle = 0`);
- PE-подсистема — `Windows GUI (2)`, консольного окна не появляется;
- размер — около 49 КБ (в пределе < 100 КБ), иконка встроена.

## Если csc не компилирует

Покажите точный текст ошибки от `csc.exe` — по нему видно причину (нет прав,
битый `app.ico`, синтаксис). Запасной вариант — **PS2EXE**, но он требует
отдельной установки модуля, поэтому в этом проекте не используется и
автоматически не ставится. Лончер намеренно оставлен на чистом `csc.exe`,
который уже есть в Windows.

## Примечания

- .exe не подписан. При первом запуске SmartScreen может показать
  предупреждение — это нормально для локально собранного файла
  («Подробнее» → «Выполнить в любом случае»).
- Антивирус может реагировать на любой .exe, запускающий PowerShell;
  исходник `launcher.cs` открыт и предельно короткий — при необходимости
  соберите .exe сами тем же `build-exe.ps1`.
- Копия готового `DomMonitor.exe` лежит также в `C:\esp32\tools\` рядом с
  боевыми скриптами.
